# 2026-10-22 기능 보완 및 검증

## 구현 내용

- 최근 50개에 제한됐던 대화 기록에 **이전 메시지 불러오기**를 추가했습니다. 이전 기록을 붙일 때 스크롤 위치를 유지합니다.
- 기록 API에 `before`와 `after` ID 커서를 추가했습니다. 두 값을 함께 쓰거나 잘못된 범위를 입력하면 400을 반환합니다. 조회 권한은 기존과 같이 방 구성원에게만 부여합니다.
- 재연결·탭 복귀 시 마지막으로 조회 완료한 ID부터 50개씩 반복 조회합니다. 실시간 수신 ID와 조회 완료 ID를 구분해 복구 도중 들어온 메시지 때문에 누락분을 건너뛰지 않도록 했습니다.
- 서버 메시지 ID로 말풍선을 중복 제거하고 정렬합니다. 이전 방의 늦은 응답이 현재 방에 표시되지 않도록 화면 요청 버전을 검사합니다. 목록으로 돌아가면 방 구독을 해제합니다.
- 새 대화방·메시지·읽음 변경을 `/user/queue/rooms` 개인 큐로 알립니다. DB 커밋 이후 발행하며 수신자는 기존 트랜잭션에서 확정합니다. 알림 누락에 대비해 보이는 탭에서 15초마다 목록과 대화를 보완 조회합니다.
- 대화 목록을 최근 메시지 순으로 정렬합니다.
- 같은 메시지 ID로 재전송할 때 **발신자·방·내용**이 모두 같아야 기존 결과를 반환합니다. 다른 방의 메시지가 재전송 결과로 노출되거나 다른 방 토픽에 발행되는 문제를 막았습니다.
- 방 행 잠금으로 동시 전송·재전송을 직렬화합니다. 같은 사용자 쌍의 동시 방 생성도 사용자 행 잠금으로 중복을 방지합니다. STOMP 프레임 수신·발행 순서도 보존하도록 설정했습니다.
- WebSocket 구독은 구성원인 방의 정확한 경로와 두 개인 큐만 허용합니다. 와일드카드·다른 사용자의 큐 구독, 브로커 토픽 직접 발행을 차단합니다.
- STOMP Client가 소켓 종료 후 ACTIVE 상태로 남아 `activate()`를 무시하던 재연결 문제를 수정했습니다. 연결 시도에는 10초 제한을 둡니다.
- 모바일 목록 복귀 버튼, 동적 화면 높이, 가로 넘침, 말풍선 줄바꿈과 긴 이름 표시를 수정했습니다.
- 한글 조합 중 Enter가 전송되지 않도록 했습니다. 일반 HTTP의 LAN 접속에서도 `crypto.getRandomValues`로 UUID를 생성합니다.
- 사용자 검색 응답의 순서 역전과 검색 실패 표시를 보완하고, 검색 결과·방 목록을 키보드로 선택할 수 있도록 했습니다.

## 자동 검증

```bash
./mvnw test
```

기본 테스트 **18개 통과**, 실제 Ollama 품질 평가 **3개 건너뜀**.
기존 7개 테스트에 다음 11개를 추가했습니다.

- 대화 125개의 최신·이전 페이지 조회와 전체 복구, 조회 권한·커서 유효성
- 재전송 발신자·방·내용 검증 및 ID 길이 제한
- 동시 재전송의 단일 저장과 양쪽 사용자의 동시 방 생성
- 연결 풀 4개에서 동시 작업 12개로 메시지 24개 전송
- 최근 메시지 기준 방 정렬
- WebSocket 전송 목적지, 와일드카드 구독, 개인 큐·방 구성원 권한 검사

## 실제 브라우저 검증

Python Playwright와 설치된 Chrome의 별도 세션 두 개로 확인했습니다. 테스트는 서버에 임시 계정과 메시지를 생성하므로 독립 인메모리 DB 서버에서 실행합니다.

터미널 1:

```bash
./mvnw spring-boot:run '-Dspring-boot.run.arguments=--server.port=18080 --spring.datasource.url=jdbc:h2:mem:webtalk-browser --debug=false'
```

터미널 2 (Python Playwright 설치 필요):

```bash
python3 -m pip install playwright
python3 -m playwright install chromium
python3 scripts/browser-smoke.py
```

이미 설치된 Chrome을 사용하려면 `--chrome '/실행/파일/경로'`를 추가합니다. `--screenshots-dir docs/screenshots`로 실행 화면도 저장할 수 있습니다.

확인한 결과:

- 새 대화방을 4초 안에 상대방 목록에 표시
- 양방향 송수신, 줄바꿈 보존, 한글 조합 Enter, 일반 HTTP용 UUID 대체 경로
- 메시지 62개 중 처음 50개 표시 후 이전 12개 조회
- WebSocket 연결을 차단한 동안 새 메시지 65개 저장 후, 재연결 시 누적 127개를 중복 없이 서버 ID 순서로 복구
- 모바일 390px 화면에서 목록 복귀, 화면의 가로 넘침 없음
- 다른 방에 있을 때 안 읽은 수 증가, 방을 열면 읽음 처리 후 숫자 제거
- 잘못된 커서 요청의 400 응답과 브라우저 JavaScript 오류 없음
