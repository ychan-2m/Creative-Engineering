# 2026-10-22 추가 실행 점검

실제 Spring Boot 서버를 별도 포트 18080과 인메모리 H2로 실행하고, Chrome의 독립 브라우저 세션 3개로 점검했습니다. 기존 파일 DB와 계정은 수정하지 않았습니다.

## 재현 후 수정한 문제

| 문제 | 재현 방법 | 수정 결과 |
| --- | --- | --- |
| 다른 상대에게 이전 초안이 표시됨 | Bob에게 쓰다가 Charlie 방으로 이동 | 방마다 초안을 분리하고 돌아오면 해당 방의 초안을 복원 |
| 실패한 메시지가 방 전환 후 사라짐 | 연결을 끊고 전송한 뒤 다른 방으로 이동·복귀 | 미확인 메시지를 방별로 복원하고 연결 복구 후 같은 ID로 재시도 |
| 보지 않은 새 메시지도 읽음 처리됨 | 메시지 목록을 위로 올리고 상대방이 전송 | 최신 위치에서만 읽음 처리하고 ‘새 메시지 · 최신으로 이동’ 표시 |
| 말투 설정의 미저장 편집이 사라짐 | 설정 내용을 편집하고 닫거나 Escape 후 다시 열기 | 같은 탭에서 임시 편집을 유지 |
| 만료된 로그인 상태로 채팅 화면에 머묾 | 같은 세션을 로그아웃한 뒤 검색 API 요청 | WebSocket 연결을 종료하고 만료 안내가 있는 로그인 화면으로 이동 |
| 기록 조회와 후속 동기화 실패가 같은 재시도로 처리됨 | 기록 API에 일시 503 응답 주입 | 최초 기록 실패를 별도로 관리하고 ‘다시 불러오기’로 정상 복구 |

읽음 요청 중 메시지가 추가된 경우도 다음 읽음 요청으로 이어 처리하도록 보완했습니다. 브라우저 테스트는 설치된 Chrome을 자동으로 찾아 실행하며, 예상하지 않은 alert도 실패로 판정합니다.

## 검증 결과

서버 자동 테스트는 **18개 통과, 실패 0개**입니다. 실제 Ollama 품질 평가 3개는 기본 설정대로 건너뛰었습니다.

브라우저 실행은 다음 **13개 묶음이 모두 통과**했습니다.

1. 새 대화방 실시간 표시
2. 양방향 송수신, 줄바꿈, 한글 조합 Enter와 UUID 대체 경로
3. 이전 대화 페이지 조회
4. 단절 중 메시지 65개를 누적 127개로 중복 없이 복구
5. 모바일 크기의 목록 복귀, 안 읽은 수·읽음 갱신
6. 키보드 검색과 상대별 초안 분리
7. 전송 실패 후 방 전환·복귀·재연결·재시도
8. 과거 대화 읽는 중 스크롤과 안 읽은 상태 유지, 최신 이동 후 읽음
9. 기록 조회 503 오류 후 수동 재시도
10. 말투 편집 유지·저장·삭제, 모의 AI 503 오류 및 후보 선택
11. 세션 만료 후 로그인 화면 안내
12. 로그인 실패·성공·로그아웃 UI와 로그아웃 후 API 401
13. 브라우저 JavaScript 오류와 예상하지 않은 alert 없음

AI 장애와 추천 후보는 브라우저에서 API 응답을 모의로 주입했습니다. 실제 모델의 답변 품질이 검증되었다는 뜻은 아닙니다. 말투 저장·삭제는 실제 서버 API로 확인했습니다.

## 재현

`webtalk` 폴더에서 다음 서버를 먼저 실행합니다.

```bash
./mvnw spring-boot:run '-Dspring-boot.run.arguments=--server.port=18080 --spring.datasource.url=jdbc:h2:mem:webtalk-recheck --debug=false'
```

다른 터미널에서 실행합니다. Python Playwright가 필요합니다.

```bash
python3 scripts/browser-smoke.py --screenshots-dir docs/screenshots
```

설치된 Chrome을 자동으로 찾습니다. 찾지 못하면 `--chrome '/실행/파일/경로'`를 지정하거나 Playwright Chromium을 설치합니다. 이 스크립트는 테스트 계정과 메시지를 생성하므로 독립 테스트 서버를 대상으로 실행합니다.

## 남아 있는 한계

- 초안·실패 메시지·미저장 질문지는 현재 탭 메모리에 보관합니다. 방이나 설정창을 바꾸어도 유지되지만 새로고침하거나 탭을 닫으면 사라집니다. 서버가 저장 확인한 대화 기록은 DB에 남습니다.
- 실제 Ollama 답변 품질과 속도는 별도 평가가 필요합니다.
- 모바일은 Chrome의 화면 크기로 검증했습니다. 실제 휴대폰의 가상 키보드, 터치와 서로 다른 외부 네트워크 접속은 별도 점검이 필요합니다.
- STOMP.js를 외부 CDN에서 읽으므로 초기 로딩에는 해당 CDN에 접속할 수 있어야 합니다. 오프라인 알림·파일 전송·다중 서버 확장은 아직 후속 범위입니다.
